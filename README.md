## 从干净检出玩一局（本次已复验）

```bash

```

打开 `http://127.0.0.1:<port>/index.html?slice=1&style=grow&seed=1`。页面停在第一屏，
先选**开局**（争街 / 整条街，默认争街），再选一张起手（街角店主 / 机会买家 / 穿街高手），
然后点「开一局街角生意」。

**开局那一格决定你这一局能走哪条路**，不只是画面。下面每一条都按**你坐的那张椅子**写 ——
这张表和「一般意义上的争街」不是一回事，而且三个座位拿到的牌并不对称。
依据是 `support/probe-3391/human-half.mjs`：真实入口（`human:true`）、三个起手 × 5 个 seed，
四条硬断言，任一不成立就抛（现在 15/15 局全成立）。

**你的椅子（0 号位）：两条街的另一半都是无主空地。**

- 你拿到两间店，分在两条不同的街上：晨光街一间、月色街一间。
- 这两条街的另一半（4,1 / 8,9）**开局都是无主空地，并且都已建成 Lv.1**。
- 买它们就是**买地**：走过去按标价 8,000，等级当天继承；不经过收购卡，也不等谁先开张
  （`buyPrice` / `buyPlot` 只看等级与标价，`availableFromDay` 只约束书屋）。
- 「只买己方那条街的另一半」这种意图，60 seed 里每局真的买 **1.25–1.32 次**。

**两个对手的椅子：他们的另一半才是对方的店。**

- 两个对手（机会买家、穿街高手）的两条街互为对方（4,9↔3,9、8,1↔9,1），**没有空地可买**。
- 他们要补齐只能走收购卡，而收购在实测里是负期望 —— 所以这条计划在他们手上基本不发生。

所以「买下另一半，这条街就归我一个人」这句话，在**你的椅子**上是「走过去按标价补齐」，
在**对手的椅子**上才是「收购」。这是座位差别，不是两种公平的打法，别把它当路线去追。

**`?cross=0`（整条街）**：你开局就独享整条街，同街加成 t=0 就满了。
补齐这件事在这里**不存在**：同一支量具里「只买自己那条街的空地」60 局买地 **0.00 次**，
因为那条街上没有空地可买。

两张表都量过（同一支 `support/probe-3344/openings.mjs`，60 seed/格 × 2 座位排列）：
争街的破产率 3.3/9.2/5.0%，整条街是 13.3/13.3/11.7%；每局真付租 3.58/局 vs 3.10/局。
**但争街不是更公平**：起手差距在这两个样本量下都不是零（见下面的胜率与区间）。

**补齐一条街值不值得做？不值得，而且比「略亏」严重得多。**
`support/probe-3391/two-routes.mjs`（三把椅子轮换、每格 2,700 局）里有一条必须看清的口径：
那个「只补齐」的臂**只在它本来想买/加盖书屋时才改写 AI 的答案**，所以在 **66.9%** 的局里
它一次都没在场（`free` 表 60.5%），那些局与照常打逐字节相同、配对差恒为 0。
把空臂摊进全部局，读数就被稀释成 **−15.9pp**；只看**臂真的在场**的局：

| 表 | 全部局 | 仅生效局（空臂率） |
|---|---|---|
| 争街 | −15.9pp | **−48.0pp [−51.5, −44.7]**（66.9%） |
| 整条街表 `free` | −17.2pp | **−43.5pp [−46.7, −40.2]**（60.5%） |

三条起手在仅生效局里同号（争街 −36.5 / −51.8 / −53.0）。
⇒ **只抢书屋是当前唯一有效的支出方向**；补齐不是「略亏」，是「真走这条路的人 −43~−48pp」。
反过来读也成立：**在大多数局里，它连选项都不存在** —— 没有书屋可拒，这一臂就无事可做。
**「营业进项」也不是第二条打法 —— 它是给人类这张椅子的一次补贴，而且已经不占首屏。**
它默认关闭，只在地址栏显式打开：`?slice=1&business=250`（省略或 0 就是正式规则）。
为什么从首屏撤掉：首屏高度被窄视口卡过两次，加上那一排实测把「开一局」从 757 顶到 854
（390×844 视口 844）、360×640 从基线 773 到 813（`support/compare/layout-smoke.mjs`）；
而这条规则本身量下来的结论是「只在人类座位有效（进项 3.97×），三把椅子平均整体 **0.0pp**，
把对手那份收益补齐后，它与「白给同样多的钱」分不开（−0.9pp [−3.5, 1.7]，跨 0）」
——它不配占首屏最贵的位置。
完整的边界、几何根因与四组反证见 [RESULT-3391u](docs/evidence/RESULT-3391u.md)。

胜率**不一样**：同一套 AI、走真实入口、**默认争街开局**、每格 300 局，目前是
53.7% / 36.3% / 44.3%，最弱与最强相差 17.3 个百分点。
（95% 区间：街角店主 48.0–59.2% / 机会买家 31.1–41.9% / 穿街高手 38.8–50.0%。）
逐对看：街角店主↔机会买家 **分得开**；街角店主↔穿街高手 区间重叠；
机会买家↔穿街高手 区间重叠。也就是说能确定的只有「街角店主比机会买家强」。

**第一回合真正要作决定的地方**：起手只是选打法，第一个有后果的选择在局内。
「机会买家」的收购卡是第一处被修好的：它以前把**空地**也当目标，而对任何目标都收 125%
（那 25% 是付给原主人的溢价，空地没有原主人）——于是每个目标都凭空亏 2,000，
AI 在 40/40 局里一次都不用这张卡。现在它只收**别人已开张的店**，选目标那一屏
t逐个列出「买下后每局大约能收多少」，因为四个候选的价与标称租金完全一样，
真实差别在**哪条街有人走**（n=300 同种子实测：灯火街 19.3%，晚风街 5.0%）。
改完平衡表**逐位不变**（45.7 / 32.0 / 34.7）—— 修的是合法目标与呈现，不是力度。
细节与反例见 [RESULT-3332](docs/evidence/RESULT-3332.md)。

**更早的一处：第 1 天第 2 个决策就是「加盖 10,000」。** 街角店主与穿街高手的起手带「翻修」卡，
所以这一屏其实是一个三选一，而改前只印了三个数里最好看的那个（「估值增加 4,000」，
而当场总资产是 **−6,000**）。现在它把当场三笔账并排给出，并说明那张免费卡能做什么：
不付的话，那张卡下回合免费把它升到 2 级；要到 3 级，先付再免费共 10,000、先免费再付要 15,000。

细节、两个负对照与 390×844 的几何读数见 [RESULT-3334](docs/evidence/RESULT-3334.md)。

**那张加盖屏在旺季里改说「还能收几次」，而且这个次数不是期限（#3456）。**
旺季里那几次得在旺季结束前踩到，所以句子带期限；但期限不等于次数上限 ——
切片里每人一天一个回合，而**两位对手可以在同一天各踩到同一格一次**
（180 局真实整局里 882 个「店×天」有 18 个当天两笔，约 2.0%）。
所以窗口容量是「当天敌对座位数 × 剩余天数」，屏上只留一句能做决定的话：
「3 天内最多收 6 次：2 位对手每天各来一次」。剩余 1 天那一档同理写「1 天内最多收 2 次」，
不会因为「只剩一天」就说只能收到 1 次。
同一屏还给一笔跨季节的例子（旺季踩 2 次收回 8,000，剩 2,000，之后按平常价再 1 次就够），
三个数都能拿屏上已有的两个单价逐位复算。
要说清的是：「最多」是**上界，不是期望值**。同一屏还给一张**同规则 72 局的实测分布**
（「这间店整局被踩到：0 次 66 局 / 1 次 6 局 / 2 次及以上 0 局」）—— 它说的是这一格过去被踩到几次，
不是概率，也不是本局的预测；两个数并着看，才知道「上界」离「常见」有多远。
自己复核：`node support/probe-3391/print-season-screens.mjs`（把剩余 0–3 天的原句整段打印）、
`node support/probe-3391/same-day-landings.mjs`（数当天两笔）、
`node support/probe-3391/cap-vs-settlement.mjs`（用产品自己的结算行核对「笔数 ≤ 当天对手数」）。
证据、判据与边界见 [RESULT-3456](docs/evidence/RESULT-3456.md)。

与本局无关；其中「带现金收购别人养好的店」实测是**最差**的一条路（同 seed 配对 300 局：

**买地和打完后的那句建议，现在说的是同一份账。** 上一版两屏打脸：买地时劝退
（「72 局里有 56 局的整局租金还不够这一笔」），打完却叫你「第 4 天开售就去拿街心书屋」。
根因不是文案，是口径：买地是**资产换手**，不是花掉 —— 真 `buyPlot` 前后总资产差 0
（现金 −26,000、地产标价 +26,000，三种起手都一样）。租金要盖的不是那 26,000，
而是这笔现金被占住的机会成本。现在两屏共读 `src/engine/market-ledger.js`：
买地屏给三行（本局总资产不变 / 买完剩多少、够付对手最贵的一次租几次 / 72 局里对手踩到它几次），
结算屏按同一份表说话，并且不再叫你自己走到自己店旁边 —— **自己的店不收自己的租**
（实测：我持有书屋的 31 局里，31 局都发生过「我自己停在它旁边」，合计 155 次，一分钱没有）。
顺手修了三个真缺陷：书屋加盖报 15,000（引擎实际扣 30,000，那是小店价）；
买不起时屏上算「现金 13,000 → -13,000」「够付 -3 次」；终局停业时旺季那句写成「0 变 0」。
见 [RESULT-3338](docs/evidence/RESULT-3338.md)；复算：
`node support/probe-3338/ledger-table.mjs 24`、`node support/probe-3338/geom.mjs`、
`node support/probe-3338/settlement.mjs`。

**选落点那一屏：自己的店不再被印成一个租金。** 定步是全游戏唯一由玩家直接选落点的地方
（3.46 次/局、20.8 个点选项/局），而它原来把自己的店写成「己方 · 租 2,800」——
引擎在自己的店旁只问「要不要加盖」，一分钱不收（`flow.js` 付租分支第一句就 `continue`）。
实测这些行占 25.1% 的点选项，其中 89.7% 的那个数比同屏所有对手租都大、33% 是那个点数下唯一的信息，
均值 5,669：**最能拉动你选那个点数的数，在自家店上不会到账**。
现在写引擎真会做的事：`你的店 Lv.1 · 停在这里可加盖 10,000`（到顶/停业时说「自己停在这里不收租」），
对手的店写明「付租 2,800」。改后 5,977 个点选项里 0 个再出现旧的假数。
同一片里也量清楚了**为什么现在只有一个打法**（买书屋）：45.2 回合/局，52.6% 的落点挨着地，

### 第二入口（8001 对照页）

对照页 `/.scratch/af-variant.html` 需要一个额外的静态服务，**唯一权威入口是 `support/serve-variant.py`**：

```bash
python3 -B support/serve-variant.py 8001
# 打开 http://127.0.0.1:8001/af-variant.html
```

`support/serve-variant.py` 与 `serve.py` 同一套内部目录拦截（但不拦 `.scratch` —— 对照页只能从那里取），
并且同样支持 `python3 -B support/serve-variant.py 0` 由系统分配端口（stdout 会打印 `LISTENING <port>`）。

> 历史：这个入口原先住 `.scratch/serve-variant.py`。`.scratch` 是例行清理的 ignored 目录，
> 2026-11-22 被清掉后，仍在跑的 8001 进程 argv 指向了一个已不存在的文件 ——
> 重启会直接失败。现在副本在 `support/`（随仓库走），`tools/verify-full-game.mjs` 与
> `tools/verify-grow-panel.mjs` 也都用 `support/` 的路径起服务。

## 现在能玩什么

- **大酒店地图**：27×19。中央是一块 3×3 的大酒店，四周 12 个路面格全部与它相邻；四角各有 2×2 大地产，被三条路包住，形成 6 个入口。
