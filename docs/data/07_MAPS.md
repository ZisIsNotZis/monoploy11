## 1. 先分清三件事（这决定了「16 张图」怎么数）

### 1.1 模式：传统 / 热斗 `[C]`

官方原文（S3、S4、S6）：

- **传统地图**：延续系列经典玩法。「以道路连接小地产、大地产、银行、乐透、商店、新闻、魔法屋等功能各异的地图格。投资小地产是传统地图上主要的盈利方式。」同一街道的房产**合并计算租金**——停在对手一处房产，结算的是整条街（S5）。
- **热斗地图**：始于《大富翁 10》。「小地产格子将被地雷、飞弹、炸药等攻击型卡片格取代，使用攻击型卡片直接给对手造成金钱伤害是热斗地图的取胜机制。」「地图上只有大型地产且不会受到伤害卡影响。」路径「更加密集交错」，官方建议「在转角和丁字路口上放满地雷」（S6、S5、S3）。

### 1.4 机关是什么 `[C]`（官方定义，S2/S3）

> 「机关是地图中一类特殊的格子或者环境效果，在不同的地图上有不同的功能。机关启动后，**可能改变道路的走向或者连接方式，可能造成银行、商店等功能格的开启或者关闭，还可能打乱地图上地雷、炸药、定时炸弹等道具的位置**。」

⇒ 对拓扑复刻而言，机关就是**边的开关**（改连接）、**节点的开关**（功能格启用/禁用）、**道具位置的扰动**。三类要在 IR 里分开建模（见 §18）。

### 1.5 格子的占位规则：一个格子只能有一个「东西」

这条是**规则**，但它的落点在**地图数据**上（哪类格能放、刷在哪、刷多快），而且 `06_SYSTEMS.md` §11.4 已把「各地图机关/遭遇的触发格与效果表」明确让给了本文件。所以规则正文归 `06_SYSTEMS.md` / `08_RULES.md`，**本节只写它对地图数据的要求**。

#### 1.5.1 规则本身（EXPLICIT，来自工作包补充指令）

> 同一路面格只能存在一个放置物/遭遇物（神仙、道具、野狗、尸体、神秘商人、地雷、定时炸弹等）；有东西的格子玩家/AI 不能再放，自动刷新也会跳过。一个格子可以站多名角色。

⇒ **站位与占位是两个独立维度**：

| 维度 | 基数 | 谁占用 |
|---|---|---|
| 角色站位 | **多值**（一格可站多名角色） | 角色不排斥角色 |
| 放置物/遭遇物占位 | **单值**（0 或 1） | 物体占格，且**排斥一切新的放置与自动刷新** |

这两条必须分开存，不能用一个 `occupied: bool` 混在一起——否则「两人同格」和「格上有地雷」会互相误杀。

#### 1.5.2 哪些格是「放置格／遭遇格」

可确证的只有一条**通式**，细表**全部【未证实】**：

| 格类 | 能否承载放置物/遭遇物 | 依据 |
|---|---|---|
| 普通路面格（含 `+2000/-5000` 这类金钱格、空地产格） | **能** | 天使岛实机近景截图中可辨识出犬形非玩家生物（野狗一类）站在**普通路面格**上；且放置类卡片（地雷/炸药/香蕉皮/果冻墙）按官方说法是「使用卡片放置」到路上（S2） |
| 功能格（银行/商店/魔法屋/乐透/新闻/医院/监狱/车站/传送点/起点） | **【未证实】** | 没有任何资料说能不能；**不要默认不能**（地雷埋在银行门口是这类游戏的经典玩法） |
| 机关格 / 大建筑格 | **【未证实】** | 同上；机关格自身可能就是「放置物」的宿主 |
| 已占格 | **不能**（再放置被拒，自动刷新跳过） | EXPLICIT（1.5.1） |
| 不可行走格（地图外、纯装饰） | **不能** | 不是节点，不在 `V` 里 |

⚠ 复刻时的安全选择：**先把「可承载」默认设为该图所有可行走格**，把例外做成数据开关；不要把「只能放在空地」这类未经证实的限制写死。

#### 1.5.3 刷新点与刷新规则

- **刷新点（spawn point）不是一种格类，而是一组格 id**：它是「野狗/乞丐/神秘商人/神仙等遭遇物会在哪里冒出来」的白名单。
- **刷新规则**（自动刷新的时机与频率）：**【未证实】**。已知的只有约束面：①刷新目标格必须是可承载格；②刷新目标格必须**当前为空**（EXPLICIT）；③机关会「打乱地雷/炸药/定时炸弹的位置」（S2/S3），这是一次**重排**，重排后的目标格同样受 ①② 约束 `[I]`。
- **逐图刷新点位置与密度**：**全 16 图【未证实】**。截图上能看到野狗/遭遇物的**实例**，但那是随机刷新的结果，**不能反推刷新点表**，也不能拿来算密度。

#### 1.5.4 对拓扑与 AI 的直接影响（复刻必须体现）

1. **放置类卡片的合法目标集 = 可承载格 − 已占格**。AI 选点必须先做这个集合运算，否则会不断尝试非法放置。
2. **小图先耗尽**：骑士庄园/雪国这类单环小图，可承载格少，几步内就会被地雷/炸药/遭遇物填满，**放置类卡片会自然失效**；水乡/不夜天这类大网格则长期有空间。这是拓扑对卡片价值的直接调制 `[I]`。
3. **不夜天「格子随时间变化」与占位冲突**：若某格要变内容而它上面正站着放置物，是先清空还是跳过？**【未证实】**（已列入 §18.6 待复核）。
4. **「一个格子可站多名角色」是追债/结盟的拓扑基础**：同格玩家之间不需要经过边就能互动（换卡、组队加成、平分遭遇），因此**瓶颈格（车站、传送点出口、中央枢纽）不仅是路径瓶颈，也是交互热点** `[I]`。

#### 1.6 岔路、监狱医院与活动机关板（EXPLICIT，用户口述）

这四条是**每张图都必须满足的拓扑约束**，实现时写进地图校验器，不靠手工自觉：

1. **没有死路**。所有支路必须回到主路或另一个节点；若某条路确实是死路，它的末端节点**无条件是一个随机传送门**（踩到即随机传送到地图上任意路面），不能是普通格。
2. **岔路方向规则**：
   - 移动途中**没有正好停在交叉点**：在交叉点从「非来路」的出边中**随机**选一条继续走。
   - 移动**正好停在交叉点**：由玩家**选择**下一步方向（或选择朝向，待实测确认是“立即续走”还是“下次前进方向”）。
   - 这条规则只对度数 ≥ 3 的节点生效；度数为 2 的节点按唯一出边继续。
3. **监狱与医院**：每张图至少各一个；二者都通过**一条侧路**连回主路，不把入口直接摆在主环上。
4. **活动机关板**：周期性出现/消失；消失时若有人站在上面，角色**自动移动到最近的非活动机关板格**（距离按图上的步数，不穿墙；同距时的选择规则待定）。
5. **一格多人无副作用**：同格角色不互相阻挡、不额外收费、不改变落点结算；相遇交互另行定义。

> 校验器至少要能报：死路末端不是传送门、监狱/医院缺失或没有侧路、交叉点度数与方向规则冲突、活动板没有“最近稳定格”映射。

## 2. 骑士庄园（传统）· CONFIRMED

**图证**：S1 截图 `https://img1.gamersky.com/image2022/10/20221013_xdj_187_1/14360.jpg`

- **模式**：传统（→ 亦可跑抢房规则）。
- **适合人数**：原版单图不设人数上限，比赛支持 2–4 名玩家（挑战模式为 4 玩家 + 1 领主）。**逐图推荐人数无公开资料【未证实】**。结构上是最小的一张，人多了会挤 `[I]`。

  - ⚠ 保守声明：截图中若干格带有**交叉纹理标记**（雪国、水乡、云上庭院里也有同样纹理），这些标记是普通花色还是**岔路/交叉口**，本文件**无法判定**，标【未证实】。若实机证明它们是岔路，本图应从「单环」修正为「单环 + 若干交叉」。
- **机关**：**无** `[C]`（S1 未提，截图无旋转/传送类构件）。
- **车站 / 传送点**：**无** `[C]`。
- **特殊格分布**：沿环散布小地产（灰格）与已标价的地块；可见的功能图标有魔法屋（紫）、银行（蓝）、商店、乐透、新闻、医院/监狱类图标，以及 `+2000 +5000 -2000 -5000 -10000` 的金钱格与红色 `!` 事件格。**具体数量与相对位置未逐一核对【未证实】**。大建筑成组集中在环内四角。

## 18. 给复刻用的拓扑数据模型（把这 N 张图变成同一套 IR）

本节的目的是让「拓扑等价」变成可检查的东西，而不是画得像。

### 18.1 图模型

```
Node = { id, kind, ... }
  kind ∈ { tile, property_small, property_big, bank, shop, magic, lottery,
           news, hospital, jail, start, station, teleport, mechanism, event,
           attack }   // attack = 热斗图的攻击卡格（格子的固有属性，不是 occupant）
Edge = { a, b, dir ∈ {fwd, both}, gate: GateId | always, cost: int = 1 }
Gate  ── 机关造成的开关；GateId 由机制节点/全局相位驱动
```

**占位与站位是两组独立字段（见 §1.5）**：

```
Node.placeable : bool        // 能否承载放置物/遭遇物；安全缺省 = 所有可行走格 true
Node.occupant  : ObjectId|∅  // 单值！同一时刻 0 或 1 个放置物/遭遇物
Node.characters: Set<CharId> // 多值！一格可站多名角色，角色不排斥角色
Node.spawn     : bool        // 是否属于某遭遇物的刷新点白名单

不变量 INV-1: 若 Node.occupant ≠ ∅，则 place(该格) 失败、spawn(该格) 跳过。
不变量 INV-2: |Node.occupant| ≤ 1，且 occupant 的写入必须通过带 INV-1 检查的单一入口。
不变量 INV-3: Node.characters 的基数不受 INV-1/INV-2 影响。
```

把 INV-1/INV-2 做在数据写入的**单一入口**上（而不是散落在各调用点），这个错误就无法被表示——这是本工作包里最值得做成「不可表示」的一条。

- **传统图**：`cost = 1`，无 gate，边集静态（除非该图有机关）。
- **热斗图**：没有 `property_small` 节点；攻击卡格是一种 `kind = attack` 的节点，落上去＝获得攻击卡。
- **抢房规则**：不改图，只改 `property_*` 节点的**初始状态**（部分初始地块自带建筑）。

### 18.2 机关的三类，分别建模（对应 S2/S3 的官方定义）

| 官方表述 | IR 里的落点 | 本文件已确证的图 |
|---|---|---|
| 改变道路的走向或连接方式 | `Gate` 切换 `Edge` 的连通 | 机械迷宫（旋转枢纽）、山城（索道支路）、天使岛（隐藏路线，细节未证实） |
