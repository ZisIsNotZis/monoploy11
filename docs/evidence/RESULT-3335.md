# #3335：同一句「下回合」被说在没有下回合的地方

上一片（`90f15f9`）的两处收尾。未推送。

## 结论（先看这里）

主管在 390×844 真机上实点 `90f15f9`，抓到两件事，都是我的交付缺陷：

**① 最后一屏讲了一个不存在的动作。** seed 4 · 街角店主把「翻修」卡留到第 16 天，
停在晨光街小店时屏上仍写：

> 不付：**翻修卡下回合**免费升到 2 级。两步到 3 级，先付再免费 10,000 / 先免费再付 15,000（差 5,000）。

第 16 天是 `dayLimit`。当场按「放弃」= 直接结算，**没有下回合**，那张卡再也用不上。
旧句不只是「不精确」：它把这条分叉里唯一真正的代价（卡作废）藏在了一个不可能发生的未来后面，
而且顺手给了一个永远不会兑现的价格对比（先免后付 15,000）。

修法：`buildOrderLine` 先判 `state.day >= state.config.dayLimit`。最后一天只说这局真的还能做的事，
不再出现任何「下回合 / 下个回合」的承诺；三笔当场账（现金 −10,000 / 标价 +4,000 / 总资产 −6,000）原样保留。

**② 「可重跑」的手机复验入口指着我本机的草稿目录。** `support/probe-3334/geom.mjs`
用 `spawn('node', ['.scratch/3334/serve.mjs', ...])` 起静态服务，而 `.scratch/` 未跟踪、不入交付集。
干净副本上照 RESULT-3334 的复跑命令跑这一行会直接 ENOENT。
现在它起的是随仓库走的 `support/probe-3334/serve.mjs`（那份文件本来就在，只是脚本没用它）。
