# #3341 选落点那一屏：「可加盖 30,000」—— 而我只有 20,000

起点 `fb43938`（#3340），分支 `release/3331-starter-evidence`。**未推送、未删任何目录。**

## 监管者报的两件事

1. 穿街高手 seed 1 第 13 天，选了定步 1，落到书屋旁。落点写着「停在这里可加盖 30,000」，
   当时现金只有 20,000，到了那里加盖**确实按不了**。既然这一屏是给我挑落点看的，
   就该让我看懂**这一刻**能做什么。
2. 另有个发布入口写的是 `.scratch` 下的探针，干净检出没有那个路径。

两条都复现了，而且第二条不止一处。两条都不是措辞偏好，是**句子与引擎不一致**。

## 一、这一屏报着做不起的数

### 复现 supervisor 那一帧（改前 → 改后）

```
# 穿街高手 seed 1 第 13 天，此刻现金 20000
1 步: 街心书屋：你的店 Lv.2 · 停在这里可加盖 30,000            ← 改前
1 步: 街心书屋：你的店 Lv.2 · 可加盖 30,000，还差 10,000        ← 改后
```

引擎事实：`buildPlot` 第一句就是 `if (p.cash < cost) return;`，按钮禁用是 `(p?.cash ?? 0) < pending.cost`。
所以那句话在那一刻**永远是假的**，而它是那个点数下唯一的信息。

### 量级（120 局 = grow/take/cross × seed 1–40，`support/probe-3341/unaffordable.mjs 40`）

| 读数 | 改前 | 改后 |
|---|---|---|
| 定步屏 | 415 次（3.46 次/局） | 同 |
| 点选项 | 4,634 个 | 同 |
| **报着做不起的数、却没标出来的行** | **223** | **0** |
| ├ 加盖价超出此刻现金 | 176 / 449 行（39.2%） | 176 行，**全部**带「还差 N」 |
| ├ 买地价超出 | 22 / 211 行（10.4%） | 22 行全部带「还差 N」 |

| 其中「这是该点数下唯一的信息」 | 21 行（加盖） | 同，但已标注 |

也就是说：**最能拉动你选那个点数的数字，曾经有 198 次是你当场兑现不了的**，
其中 21 次它是那一屏给你的唯一线索。

### 两种分母，不能合成一个数

这是本片量具上最容易犯的错，所以写死在判据里：

| 动作 | 引擎看哪笔钱 | 出处 |
|---|---|---|
| 买地 | `p.cash` | `buyPlot` `if (p.cash < buyPrice(state, id)) return;` |
| 加盖 | `p.cash` | `buildPlot` `if (p.cash < cost) return;` |
| 付租 | `p.cash + p.deposit` | `pay()` `const available = from.cash + from.deposit;` 不够就是**破产** |

副产物读数：切片里 `deposit` 实测恒为 0（120 局、7,439 个人类帧，0 帧非零）。口径仍按引擎写，
免得以后加了存款就把「会破产」算错。**这也是我第一版量具的错误**：我先用 `cash + deposit` 比买地，
把「买不起」算成买得起，于是低估了 22 行；发现后改回 `cash`。

### 改了什么

`src/engine/insight.js` 一个文件：

- `landingInfo` 每块地多给 `affordable` 与三个差额 `shortForBuild / shortForBuy / shortForRent`
  —— 全部由引擎原语（`buyPrice` / `buildCost` / `rentFor`）现算，不读任何新状态。
  引擎在对手店旁还有两条「根本不用付」的岔路（停业封租、财神免租、公园），一并算进去，
  免得把「不用付」错标成「付不起」。
- `plotVisitLine` 是**唯一**措辞入口（落点说明与岔路前瞻都走它）。做不到的那一行加一句，
  做得到的**逐字不变**（`test/landing-affordable.test.js` 有一条专门钉这个，防止把屏变吵）。

写出的句子：

| 情况 | 改后 |
|---|---|
| 自己的店、能加盖、买得起 | `你的店 Lv.1 · 停在这里可加盖 10,000`（不变） |
| 自己的店、能加盖、买不起 | `你的店 Lv.2 · 可加盖 30,000，还差 10,000` |
| 自己的店、到顶/停业 | `自己停在自己的店旁不收租` / `你的店 · 停业 · 不付租`（不变） |
| 无主地、买不起 | `可买 34,000，还差 6,000` |
| 对手的店、付不起 | `机会买家 · 付租 9,600 · 现金不够，会破产` |

**没改**：引擎结算、平衡、地图、AI。付租仍然是付不起就破产 —— 这里只让它**在选之前就知道**。

### 这条判据的第一版自己就是「只在我机器上成立」

我最初用 `git ls-files` 判「文件在不在仓库里」。它在我的工作树里跑绿 ——
而 `clean-checkout.py` 建出的树**没有 `.git`**，于是判据在那个它最该工作的环境里直接
`fatal: not a git repository`，整棵干净检出被判 SUITE FAILED。

这正是本片要修的病（「发布入口写的东西在干净检出上不存在」），只不过犯病的是判据自己。
改法：把「干净检出有什么」交给**交付清单本身**（`DELIVERY.txt` 的 lock/doc/tool 行 + `test/`），
而不是问 git。这也让判据在干净检出里能跑 —— 上一版在那棵树里根本活不下来，它当然不会报错。

## 我这片被自己的量具骗了四次

1. **用 `cash + deposit` 判「买得起」**：引擎三处（`buyPlot` / `buildPlot` / 按钮禁用）都只看 `cash`，
   只有 `pay()` 才动押金。混用会低估「买不起」的行数。
2. **探针读了产品的新字段来判旧产品**：改前那个字段不存在 ⇒ 全是 `undefined` ⇒ 凭空报出 30.2% 的
   「每一行都做不起」。判据不许依赖被测对象新加的东西。
3. **`git ls-files` 判「在仓库里」**：干净检出没有 `.git`，判据在那里活不下来（详见上节）。
   判据不能依赖「我本机有而读者没有」的东西 —— 和它要防的错一模一样。
4. **第一次改 `insight.js` 时手写 splice 吞掉了一个 `push(...)` 与一个 `}`**：模块直接语法错。
   发现得早（先跑 `node -e import` 再跑测试），但那是运气；`fork.test.js` 三条红才是真正咬住它的东西 ——
   教训是**改完先跑既有的判据**，别只看自己新写的。
