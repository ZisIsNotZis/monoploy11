# #3334：正常首局最早的一处花钱决定 —— 那一屏没告诉你它换到了什么

候选 `916a872` 之上的这一片。未推送。

## 结论（先看这里）

我按上一片留下的候选，去看**正常首局最早的一处花钱决定**。从真入口走一遍，
它比预想的还早：

```
第 1 天 · 街角店主 · 第 1 个决策：动作屏（手牌 3 张，现金 42,000）
第 1 天 · 街角店主 · 第 2 个决策：加盖 小地产（停在 晨光街茶铺 Lv.1，费用 10,000）
```

（`.scratch/3334/frames.mjs`，`createSliceConfig → startSession → runGame`，与浏览器入口同一条路径；
三种起手都是第 2 个决策，take 的现金是 45,000、cross 是 46,000。）

这一屏改前**只有一个金额**，而且是三个数里最好看的那个：

> 升到 2 级；小店基础租金翻倍，最高 3 级。书屋按等级计租。剩余现金 32,000，**估值增加 4,000**。

当场真账（真 `buildPlot`，不是推算；`support/probe-3334/net.mjs`）：

| | 改前屏上 | 引擎真值 |
|---|---|---|
| 现金 | −10,000（写在「剩余现金」里，要自己减） | 42,000 → 32,000 |
| 标价 | **+4,000** ← 屏上唯一写成收益的数 | 8,000 → 12,000 |
| **总资产** | **没写** | 58,000 → 52,000，即 **−6,000** |

三种起手逐位相同（grow 58,000→52,000 / take 61,000→55,000 / cross 62,000→56,000）。
「估值增加 4,000」单独印出来读起来像赚了 4,000，而它是 **−6,000** 的中间项。

更要紧的是屏上没说这一下与手里那张「翻修」卡的关系。**引擎顺序决定了这件事**：
`flow.js` 的 `playTurn` 是 出牌(actionPhase) → 移动 → 落地 → 这个 build 提示，
所以提示出现时本回合出牌阶段**已经过去**，翻修卡只能下个回合用。于是同一条街上有三条路，
价钱不一样（真 `buildPlot` + 真 `useCard` 量的）：

| 路 | 到几级 | 花多少现金 |
|---|---|---|
| 现在付，下回合翻修卡再升同一间 | 3 级 | **10,000** |
| 现在不付，下回合翻修卡升这间 | 2 级 | **0** |
| 现在不付，之后自己付到 3 级 | 3 级 | **15,000** |

第一行与第三行差 5,000 —— 同一个 3 级，两种顺序两个价。改前屏上一个字都没有。

## 现在那一屏说什么

390×844 真 Chrome、真 CDP 鼠标输入、从第一屏点进去（`support/probe-3334/geom.mjs`）：

```
加盖 小地产
费用 10,000
升到 2 级；小店基础租金翻倍，最高 3 级。书屋按等级计租。剩余现金 32,000。
付这笔：现金 -10,000，标价 +4,000，总资产 -6,000。不付：翻修卡下回合免费升到 2 级。
两步到 3 级，先付再免费 10,000 / 先免费再付 15,000（差 5,000）。卡也可留给晨光街小店（到 2 级）。
本局账本：花 10,000，每次被踩到 2,800→5,600（+2,800）。…
同规则 72 局 …（原有背景句，逐字未动）
                                [加盖]  [放弃]
```

新加的那一段（`src/ui/slice.js` 的 `buildOrderLine`）只说引擎算得出的三件事：
**这一下当场换了什么**、**不付会怎样**、**顺序差价**。它不加推荐口气、不预测。

三种起手的分支不同，因为它们的手牌不同（这是真有区别，不是文案）：

- `grow` / `cross` 起手带翻修卡 → 拿得到上面那段完整的三条路。
- `take` 起手没有翻修卡 → 只说「手上没有翻修卡，下一级还要付 15,000」。
  这一条由判据咬着，防有人把「卡」的话安到没卡的起手上。

## 同局反事实（真入口，只改这一下）

`support/probe-3334/order-cf.mjs`，seed 1–40 × {grow, cross}，同一个 seed 各跑两臂，
**只有第 1 天这一下的回答不同**，之后全交给同一套 `aiAnswer`：

| | 付 10,000 | 不付 |
|---|---|---|
| 胜局 | 22 | 32 |
| 平均终局资产 | — | — |
| 逐局资产差 | 均值 **−9,896**（付更差） | |
| 更好 / 更差 / 相同 | 19 / 39 / 13 | |

按起手分：grow 均值 −9,045（7 好 / 16 差 / 8 平），cross −10,555。

**这**说明：在这套 AI 下，第一天就掏这 10,000 平均是亏的；但 **19 局里付更好** ——
所以它不是「一律别付」，而是一个**要看理由**的决定。屏上原先没给的就是这个理由。

### 我也测了一条自己以为会更重要的路，结果是噪声

「同样的 10,000，翻修卡是升这间（到 3 级）还是升另一间（两间都到 2 级）」：

| 起手 | 这间更好 | 另一间更好 | 相同 |
|---|---|---|---|
| grow（n=31） | 4 | 3 | **24** |
| cross（n=40） | 8 | 16 | 16 |

多数局里两条路没差别 —— 所以我把这句在屏上压缩成「卡也可留给 X（到 N 级）」两个事实，
不再解释「两间都往前走一步」。这条压缩同时也是为了装进 390px（见下）。

## 390×844 的几何：这一行差点把已签的性质弄坏

`#3264` 已签的是**这一屏内容不滚**（`max-height: min(520px,70vh)` 抬上来正是为了这个）。
我第一版那句话太长，实测：

| | 内容高 | 可视高 | 结果 |
|---|---|---|---|
| 改前（`916a872`） | 441 | 441 | 不滚，两个键 `hit:true` |
| 第一版（加了整段） | **530** | 519 | **溢出 11px**（回到「要滚」） |
| 采用版 | **511** | 511 | 不滚，两个键 `hit:true` |

两个提交键在三种版本里都 `rect [788,836]`、都 `hit:true`（`x/y` 中心点 `elementFromPoint` 命中的是它自己），
所以「点不到」这条**没有**复发；变的是「要不要滚」。

真按下也验过，不是只做命中测试：点「加盖」之后现金 `现 42k → 现 32k`，
日志写 `将 晨光街茶铺 升到 Lv.2（花费 10000），租 5,600, 4 回合回本`；
点「放弃」面板关闭、游戏继续。

## 没做到 / 不能证实

- **玩家感受未证实。** 以上全是引擎账本、真浏览器几何与 AI 对 AI 的反事实。
  最小诚实试验仍要 2–3 个真人在 390×844 上走到这一屏，复述「付了会失去什么」。
  我不知道多出的这段字是**帮**他们决定，还是只是**更长**。这是这一片最大的未知。
- **「早一回合」值多少没量。** 我测了从这一屏到玩家下个出牌屏之间**经过 2 个对手回合**
  （83 局里 82 局是 2 个，1 局是 1 个），而这两个回合里那间店**只被踩到 1 次**（83 局合计 4,000）。
  所以「现在付」买到的几乎是纯时间差；但这个数来自 83 局、且 AI 走位不代表人类走位。
- **`take` 起手那一支没有机会成本对照。** 它没有翻修卡，屏上只说了「下一级还要付 15,000」，
  没说「这笔钱本来可以买哪块地」（那句在下面的 `data-opportunity` 里已有，但两句话现在是分开读的）。
- **`gapMatches:false` 是既有的。** 已签的 `receipt-3333-final` 里同一个字段也是 `false`，
  判词 overall 仍是 PASS；这一片没有动它，也没有解释它。
- 结算屏、补给屏、窄屏以外画幅都没有重看。

## 下一处值得做

上一片留的候选里，这一条现在更清楚了：「**无合法目标的卡点了没反应**」仍然没修
（`flow.js:209` 的 `continue` 在拿不到目标时既不消耗卡也不说一句话）。它比这一片更靠近
「玩家点了一个按钮，游戏不动」这一类，只是触发概率低。另一个方向是把这一屏的
「早一回合值多少」用真的对手走位分布量出来，替换掉现在这个 83 局的粗数。
