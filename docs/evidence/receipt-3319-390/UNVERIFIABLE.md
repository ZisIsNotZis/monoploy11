# 这份回执的来源**不可核对**（保留，未删）

## 一句话

`provenance.json` 写着 `source_run: OUT-3319-final`，但那一次运行在任何地方都不存在了，
所以这份回执**能被重判、不能被核对**。它的 PASS 是真的，它「从哪来」不是。

## 实测的三条事实

取这份回执所在的目录，逐条跑出来：

1. **它自己的数字是对的。** committed 的 slim 文件与 `provenance.json` 里的 `slim`
   哈希逐项一致（89,830 / 588 / 90 字节，三个 sha256 全对）。所以「这份文件被改过」
   不成立。
2. **它点名的来源找不到。** `support/full-game/OUT-3319-final` 不存在；
   在整个工作区按字节数（317,097）找 `record-8-summary.json` 也没有结果。
3. **它记录的 raw 哈希对不上盘上任何一次运行。** 把 `support/full-game/OUT-*`
   逐个按同一套规则切一遍，`raw.record-8-summary.json.sha256` 一次都没命中。
   也就是说，它来自一次已经**被清理删掉**的运行。

   > 早先这里写过「所有还活着的 `OUT-*` 都是 `grow`/seed=1」，**那句是错的**。
   > `OUT-3319i-cross` 同样是 `cross`/seed=2，只是**另一局**（424 帧 / 64 按，
   > 而这份是 425 帧 / 64 按），哈希因此不同。所以「同一起手同一种子」不足以
   > 指认来源 —— 这也正是为什么这一轮改成把 raw 字节**装进回执**，而不是继续
   > 从残留目录里猜哪一局才是它。
   > 那一局已作为 [receipt-3319i-tree](../receipt-3319i-tree/) 单独收录，名字照实写。

`OUT-*/` 在 `.gitignore` 里，raw 帧只活在跑它的那台机器上。例行清理把它删了，
于是「回到原始记录去反对这次剪裁」这条路从那天起就断了。

## 为什么不重切一份

切不出来：raw 字节已经不在了。`make-receipt.py` 需要源目录，而源目录不存在。
凭空重跑一局得到的是**另一次运行**，不是这一份的来源；把它写成这份回执的来源，
就是用一次新的运行冒充旧的，比缺来源更坏。

## 所以这一轮怎么补

新增 [receipt-3320-390](../receipt-3320-390/)，由**真的在 Chrome 里跑完的一整局**
（`cross` / seed=2，423 帧 / 64 按，VERDICT: PASS）切出，并且改了切法本身：

- `make-receipt.py` 现在把 raw 字节用 gzip **一起发进回执**（`raw/<name>.gz`，
  317 KB → 约 16 KB），`provenance.json` 同时记 gzip 的 sha256 与**解压后**的 sha256；
- `verify-receipt.py` 让只拿到回执的人自己核：文件在不在、哈希对不对、
  slim 是不是「raw 减去声明的字段」（这一条防的是「偷偷多剪，B 项照样绿」）、
  以及**判词有没有被剪裁改变**（不是「必须是 PASS」—— 失败的回执也是合法来源，
  `receipt-3317-390` 就是一次真 FAIL）。

验证过它离开源目录也成立：把 `support/full-game/OUT-3320-final` **删掉**之后跑，
`PROVENANCE: PASS`，四项全过。

## 保留这份回执的理由

它记录的是 #3319 那一轮实际验收过的产品行为（F6/F7、390×844 整局），
删掉它等于抹掉那段证据。但它**不能**再被当成「可复核的来源」引用：

- 引用它的产品结论时，同时引用 `receipt-3320-390` 的可核对来源；
- 不要用它演示「回执可自证」——那正是它做不到的事。

`test/receipt-provenance.test.js` 会要求：任何不带 `raw/` 的在库回执**必须**有本文件，
否则测试变红。缺口可以被登记，不能被忘记。
