# #3338 买地与结算说同一份账

起点 `a7564dd`，分支 `release/3331-starter-evidence`。**未推送、未删任何目录。**

## 要解决的是什么

supervisor 在 `a7564dd` 上自己玩了两局，报了两处「作为玩家会被绕晕」：

1. **grow/seed 9**：他自己停在满级街心书屋旁边 7 次，一分钱租金没收到；结算屏却说
   「下一局把它放在你的路线上（停步的落点选它旁边），满级的租才收得到」。
   整局日志见 `/var/tmp/m11-advice-a7564dd.BtnZ5N/second-game-review.jsonl`。
2. **买书屋那一屏劝退，打完却叫他第 4 天去买**：
   「72 局里有 56 局的整局租金还不够这一笔」 vs 「第 4 天开售就去拿街心书屋」。

他同时明确了两件事：不要展开新玩法、不要刷更多种子；两屏都要在真实游戏里走一遍。

## 三处根因（都不是文案）

### ① 自己的店不收自己的租 —— 那句建议不可执行

`flow.js` 的 `groundPhase`：停在自己店旁边只走「要不要加盖」的询问；`rentFor` 只在
对手付款那一路被读。所以「把店放在你的路线上」不是一条更优的路，是一条**永远空手**的路。

量到的（`support/probe-3338/ledger-table.mjs 24`，72 局 = 3 起手 × seed 1–24）：

| 事实 | 读数 |
|---|---|
| 我持有书屋的局 | 31 / 72 |
| 其中「我自己停在它旁边」发生过 | **31 / 31 局**，合计 155 次 |
| 真到账靠对手踩到（≥2 次） | 27 / 31 局 |
| 5 局一分租金没收到 | 5 / 31 |

⇒ 变量是对手走位，不是我的落点。玩家真能改的只有两件：**等级**（到顶就没了）与
**旺季卡**（这条街 ×2，持续 3 天；实测 `sliceTargetIds('inflate')` 里包含 `market`）。

### ② 买地是资产换手，不是花掉 —— 那个分母错了

`assetsOf` 把地产按 `buyPrice` 计进总资产，而无主地的 `buyPrice` 就是标价
⇒ 现金 −26,000、地产 +26,000，**总资产一分不变**。实测（真 `buyPlot` 前后读 `assetsOf`，
3 起手 × 4 seed，`.scratch/3338/ledger.mjs`）：全是 `60,000 → 60,000`，`dAssets 0`。

所以「整局租金够不够这一笔」问错了对象：租金要覆盖的不是那 26,000（它还在你的资产里），
而是**这笔现金被占住的机会成本**。两屏方向相反，正是因为这屏比的是「花掉」，
结算屏比的是「买了 vs 没买的终局差」（同 seed 配对 40 局 +19,805，`market.mjs 300`）。
两个问法各自都对，并排印出来就是打脸。

### ③ 书屋加盖价报错了一倍

`flow.js` 的 `buildPlot` 与加盖询问都写 `pr.big ? 30_000 : buildCost(...)`。
结算屏原来用 `buildCost(lv+1)`：2→3 级报 15,000，**引擎实际扣 30,000**
（`.scratch/3338/upcost.mjs`：`charged=30000`）。这是顺手查出来的第三个真缺陷。

买完剩 18,000；此刻对手店里最贵的一次租是 5,600（灯火街小店），够付 3 次 —— 等级和旺季都会把租金再抬高。
同规则 72 局（grow/take/cross × seed 1–24）：先拿到它的 31 局里，对手踩到 0 次 1 局 /
1 次 3 局 / 2 次及以上 27 局，平均实收 11,948（5 局一分没收到）。
```

结算屏（`src/ui/slice.js`）四支全部重写；supervisor 那一局现在读作：

```

`styles.css`：顺手修了一个只有量具能看见的遮挡。「下局试试」与「再开一局」原来
是两个独立元素，句子在流里、按钮 sticky 贴底 —— 谁压谁取决于面板内容高度。

反而落到按钮中心（`elementFromPoint` 命中 `BUTTON:replay`）。现在两句打成一个
sticky 条，任何长度都带在按钮上方。

## 复核时 supervisor 又抓到两处（已修）

他拿到第一版候选后又走了两场真局（证据 `/var/tmp/m11-bookshop-review.JPa5eY/ledger-review.jsonl`），
抓到两个我自己的新缺陷。两个都是真缺陷，不是口味问题：

### ④ 买不起时，那三行账在算负数（grow/19 第 4 天）

现金 13,000、书屋 26,000，而屏上写着「现金 13,000 → -13,000」「够付 **-3** 次」。
算术都对，可用性全是假的 —— 买不起的时候玩家的问题不是「买完剩多少」，是「差多少」。
现在那一支只报两件：

```
买不起：现金 13,000，还差 13,000 才够 26,000。这笔账要等你真付得出来那天才算数。
同规则 72 局…：先拿到它的 31 局里，对手踩到 0 次 1 局 / 1 次 3 局 / 2 次及以上 27 局，平均实收 11,948。
```

保留了 72 局那一行 —— 这一屏正是玩家在想「要不要留钱」的时刻，那份表对他有用；
去掉的是所有负数。顺手把「够付 **0** 次」也改成「连一次都付不起（一次租就是 5,600）」：
同一个毛病，只是没负数那么刺眼。

### ⑤ 停业时那句旺季是「0 变 0」（grow/4 终局）

那句原来一律写「每次 rent 变 rent×2」。可 `game.js` 里 `close` 设 `closed=2`、
`inflate` 设 `inflate=3`，而 `rentFor` 先判 `closed>0` 就返回 0 —— **旺季盖不过停业**。
所以终局在停业时，两个 0 相乘得 0 是一句真数字、假结论的话。现在它说清前提：

```
这条街结束时还在停业（1 天），停业期间旺季也没用 —— 停业先结束，旺季才把 9,600 变 19,200。
```

两个数由 `holdLeversFacts` 算：停业中 `rent=0`，另外临时把 `closed` 归零读一次 `rentFor`
拿「停业结束后」的租金，再 ×2。都是引擎的值，不是我推的。

买地屏那句引导词也同时改了：原来写「买完剩多少…见下面三行」，买不起时与下面自相矛盾；
现在是「这笔钱换到了什么、还差多少（若买不起）」。

## 判据这次改在哪，为什么必须改

- `test/next-game-line.test.js`：两条旧断言把 15,000 当成书屋的价（自己也用同一个错公式算，
  所以一直绿）；另一条把「一次没被踩到」钉成「说没被踩到」就够，没管后半句叫玩家做什么。
  现在 D 项用**真 `buildPlot` 扣款**对价，并明写「不许再出现『放在你的路线上』」。
- `test/payback-pool.test.js`：买地框不再印池子句。区分标记不能再用 `同规则 72 局`
  （新表也用同一个来源前缀，这是好事），改成比池子句自己的特征串。
- `test/next-game-numbers.test.js`：新增「常数表里的数只许出现在自报来源的句子里」。
  第一版我用整句做粒度，结果把自己的新句子判红了（同一句里前半本局、后半常数）——
  判据没牙；改成要求句子内有来源标记 + 逐数回算。
- `support/full-game/run-full.py`：`len(entries) == 35` 是「当前锁几个文件」的**第二份副本**，
  加一个产品文件就撞红，而那次红说的是量具自己不会数。改成「锁无重复 + 锁的文件集
  恰好等于 `src/` 与三个根产品文件」。

## 没做到 / 不能证实

- **玩家读完会不会觉得「下一局有别的打法」，一条都没证明。** 这一片证明的是：
  句子里的数都是本局或声明的常数；两屏引的是同一份表；两种文案长度都不被按钮遮住；
  自己站自己店旁边确实收不到钱（真局抽样）。这四件都不是「玩家会改主意」。
- 「自己停旁边 7 次」这类计数来自日志原文，日志上限 400 行（真局最长约 271 行，未截断）；
  将来若截断，这个数会偏小 —— 与 `nextGameLine` 里对手那一支的处理一致，宁少说。
- 买地屏第一行恒为「总资产不变」。这是引擎的算术事实，不是我为这句写死的：
  判据 A 用真 `buyPlot` 核对；若哪天 `assetsOf` 改了记法，判据会先红。
- 没动引擎结算、没动平衡，所以平衡表没有重跑（`market.mjs 300` 只是复核旧结论仍成立）。
- 买不起那一支不再给「买完剩多少」——这是有意的信息减少：那个数一旦是负数就不是信息。
  如果将来有人想在那里加一句「再攒 N 天现金」，得先有「每天净进账」的实测，我没有。
