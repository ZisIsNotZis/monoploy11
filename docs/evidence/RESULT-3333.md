# #3333：把「每局约 +2,078，另压对手 800」讲清楚，并修掉一处会让一局走不完的卡死

## 结论（先看这里）

这一片有两件事，都是用户自己撞到的：

1. **你抓到的那句是错的，而且错两次。** 屏上写
   `灯火街茶铺 10,000（从穿街高手）每局约 +2,078，另压对手 800`，
   而同一局模型的 `perGame` 是 **1,278**。`2,078 = 1,278 + 800` ——
   **那 800 已经算在里面了，句尾又印了一次**；而且两笔的单位还不一样：
   `perGame` 是「每局」，`800` 是「对手**每次**被踩少收」。读成「多赚 2,078，再额外压 800」
   完全合理，因为屏上就是这么写的。

2. **同一处代码家族里还有一处更硬的错：一局会永远走不下去。**
   真入口、seed 173、起手 `grow`、对手 `take+cross`，第 6 天「机会买家」的回合卡死：
   AI 选「收购」→ 选目标屏 → AI 返回 `null` → 卡没被消耗 → 动作屏再问 → 无限循环。
   根因是 **AI 的候选集 ⊃ 引擎的合法集**：`slice-ai.js` 自己写了一遍买地合法性，
   漏了「空地不算」这一条（`#3332` 刚加的 `takeoverEligible`），
   于是它认为最优解是 `1,4`——一块**无主地**，引擎不认。
   `flow.js:210` 把 `null` 当「取消这张卡」，而动作屏会再问一遍同一张卡。

两句都不是估算；下面每条都有可重跑的命令和文件。

## 一、那一屏现在说什么

390×844 真 Edge 实测（`index.html?slice=1&style=take&seed=1`，点开收购）：

```
灯火街茶铺 10,000（从穿街高手）我这块每局约 +1,278 · 他少收约 345
灯火街小店 10,000（从穿街高手）我这块每局约 +862 · 他少收约 511
晚风街茶铺 10,000（从街角店主）我这块每局约 +388 · 他少收约 122
晚风街小店 10,000（从街角店主）我这块每局约 +306 · 他少收约 155
                                            [取消]  bottom 836 / 844，命中 itself
```

两笔账**同量纲（都是每局）、互不包含**：

| 项 | 怎么算 | 灯火街茶铺 | 量纲 |
|---|---|---|---|
| `perGame`（我这块） | 买下后每次租金 2,000 × 我这块每局被踩 0.639 | **1,278** | 每局 |
| `siblingPerGame`（他少收） | 对手那块每次少收 800 × **它自己**每局被踩 0.431 | **345** | 每局 |
| `net`（排序用） | 两者之和 | 1,623 | 每局 |

对照旧版：`net` 曾是 `1,278 + 800 = 2,078`（把「每次」当「每局」加进去），
句尾又印了那 800。**同一个 800 出现两次，且两次单位都错。**

真实收购前后（直接调引擎 `applyCard`，不是推算）：

```
灯火街茶铺: 成交=true 我这块收 2,000/次
   灯火街小店: 对手 穿街高手 2,800/次 → 2,000/次（少 800）   ← 这是「每次」
```

### 地图角标也一起修了

选目标时地图上原本**每一块**都印「收 10,000」：自己的两间、六块无主地、书屋——
可这张卡只收「别人已开张的小店」，它们根本不是候选（是灰色的 `pick-blocked`）。
印价等于声称那块地能收。现在只给四个真候选印「约 +N」（角标只印**我这块**，
一格放不下两笔）；其余印它本来的状态：`租 2,800` / `购 8,000` / `第 4 天开售`。

## 二、那处卡死

**实测范围（不是估计）：** `git archive 3d6762d` 的干净树，seed 1–200 × 3 起手 × 2 对手座位
= **1200 局，卡死 1 局（0.08%）**，就是 seed 173。

**为什么之前没被发现：** `balance-3332-300.json` 跑的是 **seed 1–150**，不含 173；
而且那只量具把失败记进 `failures` 却不看预算——真撞上时它会**先卡死**而不是记一笔。

**修法（两处，缺一不可）：**
- `slice-ai.js`：买地候选改问 `sliceTargetIds`（引擎的单一真相），
  自己只保留「买不起 / 太晚」这类**策略**判断。教训与 #3332 同构：
  同一件事两份实现，先漂的那份不会给出错数字，会给出**一局卡死**。
- 防守面仍在：`flow.js` 对「选目标返回 null」的处理没改（那是玩家的取消路径，行为正确）。
  但 AI 现在不会再走进它。

## 五、没做到 / 不能证实

- **玩家感受仍未证实。** 上面每一个数都是 AI 对 AI 或引擎账本。
  屏上现在说得出「我这块 vs 他少收」，但没有任何真人告诉我这样读是否更清楚。
  最小诚实试验：2–3 个真人在 390×844 上开一局、点开收购、复述他读到什么。
- **seed 173 的卡死是概率事件，不是唯一入口。** 0.08% 意味着「换一批种子还会遇到」，
  所以判据写成了属性式（扫 240 局），而不是只钉 seed 173。
- **人类玩家「反复点取消」仍会回到同一屏。** 这不是 bug（取消本就该能重来），
  但也没有任何提示说「这张卡此刻没有能收的店」。若玩家在无合法目标时点了收购卡，
  引擎会静默跳过（`if(plotIds&&!plotIds.length) continue`），屏上不给一句话。
  **这是下一处值得做的地方**，本轮没动。
- `siblingPerGame` 用的仍是 72 局实测的每局被踩次数（`RENT_POOL`），
  与小店租金同源；`街心书屋` 不在收购卡候选里，未受影响。
