# 街角生意：第一条体验切片

## 要检验的体验

用少量规则让玩家先产生打算，再看到打算成形、遭到阻力、进行调整。有限内容应形成新的选择，而非重复效果。重点不是证明已经「爱玩」，而是交付可让人判断这一点的实际版本。

保留单网页、无运行依赖、本地可玩。完整模式及 12 张地图作为已有资产保留。本切片不用长期解锁、每日奖励或更多内容来补偿对局吸引力不足。

## 当前规则（切片的权威定义；完整模式仍参照 3_REQUIREMENT）

- 3 人各自一队，默认一人类两 AI；16 天，每人每天一个回合。耗尽资金会破产；只剩一队立即结束，否则到期按资产结算。
- 起始现金按起手而定：街角店主 42,000 / 机会买家 45,000 / 穿街高手 46,000；存款 0、两间已建 Lv.1 小店、三张起手卡。小地图共有 12 间小店与中央书屋。三个起手风格改变初始手牌及 AI 偏好，不提供隐藏天赋或锁定补给。
  现金差异写在第一屏的起手卡片上（“开工现金”），因为它是影响开局最大的那个数；同一个起手，玩家与 AI 拿一样多。这三个数是按测量调出来的，但**当时那次测量的协议是错的**（固定对手顺序）；重新按真实座位量（[RESULT-3331](evidence/RESULT-3331.md)，每格 300 局，走真实入口）：改前 52.3% / 9.7% / 10.3%，改后 45.7% / 32.0% / 34.7%。所以能说的只有一句：「差距从 42.7 收到 13.7 个百分点」，不是「三条一样强」，也不是「三个起手胜率相等」。#3330 曾报 42.0 / 39.0 / 42.7 与「彼此一个标准误内」，已收回。调大现金已到尽头：held-out（seed 1001–1150）上再给 take/cross 各 +3k，读数是 41.3 / 34.0 / 45.0 —— 最弱的一条基本没动（34.3→34.0），最强的一条被压低，差距靠「换一个弱的」缩小，不是三条都变强。下一步该动的是每家起手自己的第一个有后果的选择。
- 地产落点、路面和正交相邻规则复用现有引擎。岔路可选方向，包括最后一步；回合结束不重复询问下次移动时还会再问的方向。发薪处经过 +4,000；零工格收入最多 3,000。医院/监狱仍有明显侧路，最终停在该格时转移到入口并停留两回合，预览说明这个后果。
- 书屋第 4 天开售，价格与日期在开局、地图和路线预览中公开显示。三人起点均距书屋邻接道路两步；前几天有留钱、经营或提前靠近的选择。
- 每回合最多使用两张卡，再掷一颗骰子。第 4/7/10/13/16 天各选一组两张补给，或跳过；超出 7 张手牌必须自行选择弃牌。
- 翻修：己方已建房屋免费 +1 层，最高 3 层。
- 旺季：一整条街租金 ×2，3 天。
- 停业：一整条街租金 0，2 天；不冻结旺季倒计时，可能影响同街各方地产。
- 定步：下一次掷骰固定为所选 1–6 步。可查看每个点数的所有可能落点；分岔仍需选路，不预读骰子。
- 收购：按标价 125% 购买非己方小店，原主人获得全额收购款；等级、停业及旺季状态保留。书屋不能被收购卡指定，必须实际落在相邻道路购买。
- 每三天的补给分别是：翻修+旺季、收购+定步、停业+定步。任意起手风格都能选择任意补给。
- 小店 Lv.1 基础租 2,000，逐层翻倍；同街己方已建小店每多一间加 40%。书屋 Lv.2 基础租 4,000，每次收租给主人一张五种切片卡中的随机卡。
- 普通加盖花费：小店目标等级 ×5,000，书屋 30,000。免费翻修也可升级书屋。
- 标价：Lv.1 小店 8,000；初始 Lv.2 书屋 26,000；每高于初始等级一层，小店估值 +4,000、书屋 +8,000。直接购买按标价，收购卡按标价125%。
- 总资产 = 现金 + 存款 + 各地产当前标价。不存在买下预建建筑时再重复加一次建筑价值的纸面收益。
- 切片统一使用可投资现金，收租立即进入现金；没有银行操作或锁住租金收入的存款机制。结果与租金统计按实际转账记录，破产者支付不足时不会把应付金额冒充实收。
- 本切片不刷随机路面物、神仙、股票或乐透，不启用角色天赋或五卡合成；这些仍保留在完整模式。

## 可见性与表现

决策区最频繁的一屏是动作屏（轮到人类、掷骰前）：24 局实测每局 28.5 次，是岔路屏（12.5 次）的 2.3 倍。
卡面因此写**这一局此刻**的数，而不是通用效果：翻修写「现在可升 2 栋，单栋+2,800」、收购写「现在能收购 8 块，每块 10,000–15,000」、

**收购选目标那一屏（#3333 改写）**：每个候选列**两笔同量纲、互不包含**的账 ——
「我这块每局约 +1,278 · 他少收约 345」。前者 = 买下后每次租金 × 我这块每局被踩次数；
后者 = 对手同街另一块每次少收 × **它自己**每局被踩次数。两项都是「每局」，排序用两者之和。
旧写法是「每局约 +2,078，另压对手 800」：2,078 里已经含那 800，而 800 是「每次」量 ——
重复计一次、单位还不一致（用户当场读成「多赚 2,078，再额外压 800」）。
地图角标只印**我这块**的每局数（一格放不下两笔）；非候选地照常印它自己的租金/可买价，
不再印收购报价（否则等于声称那块地能收）。判据：`test/takeover-units.test.js`（量纲与互不包含，
并用真 `applyCard` 核对前后租金）、`test/takeover-copy.test.js`（渲染出玩家真正看到的那一屏）。

旺季/停业写「最值 哪条街、每次多少」、定步写「1–6 步各自落到哪，点开就列出来」。金额一律来自 `supplyWorth`
（内部 `rentFor`/`buyPrice`），与补给屏同源，所以两屏不会互相打脸。

三条硬约束（都实测咬过人）：① 卡面**不能比原描述长到多一行**——真 Edge 1280×800 上，多一行就把第三张卡
推出 `elementFromPoint` 可点范围（实测 bottom 830 → 862）；② 规则事实不能为省字删掉（书屋须到场、
对手可封租、旺季计时照走），由 `test/slice-card-line.test.js` 钉住；③ 拼卡面不许改 state、不许读随机数。


入口 `?slice=1` 会停在第一屏等你选起手，不会替你开局。起手先选「街角店主 / 机会买家 / 穿街高手」；每张卡直接显示效果。地图直接显示店名、所有者与租金/购买价；收购时显示含溢价成本，并分别给出「我这块每局」与「他少收每局」。决策区展示现金影响、精确步数的可达落点与选路后果。自己上回合的资金变化默认就写出**来源与金额**（向谁付租、买下哪间、收购、加盖、金钱格/过起点所得），拼不齐时不写；明细仍可展开逐行核对。

**资金与资产都是 0 的回合（实测占动作屏 683/1,812 = 37.7%）例外**：这一行**整行换成**「你上回合：掷出 N 点，停在 X；这回合钱没动」（整个回合被跳过时写「在监狱中 / 在医院中 / 原地不动；这回合钱没动」），不再显示「资金 +0 · 资产 +0」。这是对 #1295「资金 +0 恒不写」的唯一例外，理由是那两个 0 什么也没说，而这句只复述日志里已有的事实。
**为什么是换掉而不是在后面补一句**：真 Edge 1280×800 同一帧实测，追加会让这一行从 1 行变 2 行（20.8→41.6px），第三张卡的中心从命中变成出视口（bottom 845.7→863.2）；换掉则行数与所有几何逐项不变。资金真变的 996 帧、资产变了的 133 帧在这一刀下**逐字未变**（渲染层对拍 996/996、133/133）。

**这一停有没有后果，也要在这一行里说清**（同样整行替换，不加行）：停在别人**停业**的店旁写「（店名）封租」，一进一出正好抵平写「收付相抵」；其余回合仍写「这回合钱没动」。这三类都只复述引擎日志原文里已有的行，不另算金额。
只在这三类**真有后果**时替换：全量 683 帧里只有 38 帧属于前两类，其余 645 帧停在没有任何地产生意的路上，没有后果可写，也不编。
「旁边是 X」的另外两种（自己的店 / 无主店）是**下一步**的提示（可以加盖、可以买），不是这一停的结果，因此不进这一行；它们仍在折叠明细与地图卡面里。
字数上限来自实测而非估计：365px 侧栏可用内容宽 343px，「掷出 6 点，停在 发薪处；晨光街茶铺封租」（最长格标签＋最长店名）自然宽 305.2px，余量 37.8px；同一帧上「…茶铺停业0租」325.8px 只剩 17.2px，而 331.2px 处已验证翻行（翻行 ⇒ 第三张卡出视口）。

**这一行恒为 1 行，由 CSS 保证而不是由字数保证**（`#insight summary` 的 `nowrap`＋`ellipsis`）。
原因是实测出来的：资金真变的回合里，**两笔原因**（过起点得钱／金钱格得钱＋付租等）会得到更长的句，
101/996 帧属于这种；在 343px 里连 49 字的压缩形状都翻行（实测 2 行、第三张卡 863.2 出视口），
而能装下的「（2 笔）」形状必须删掉金额或对象。所以改成：文本一个字不删（DOM 与折叠明细里完整逐行），
视觉上超长省略，行数不再取决于文本长度。实测最长 65 字的串仍是 1 行、第三张卡 845.7 可点。

旧的「996 帧逐字不变」因此拆成两条更窄的线：**单笔 895 帧文案逐字不变**（仍是回退线）、
**两笔 101 帧事实不得丢**（金额/对象/停业说明都必须在屏上或明细里）。结束时按资金/地产拆分资产并回看关键回合。

已知缺口：侧栏被决策抽屉盖住的那几屏（补给、弃牌、定步、加盖）看不到这一行——抽屉占满整栏是既有的宽屏取舍，不在本切片内决定。

人类出局后剩余回合只剩陪看：标题写「你已出局 · 剩下的回合只能看」，步进/AI 间隔切到 `EXPERIENCE.slice.outMs`（只缩短等待，不跳过回合、不改结算）。改前实测出局→结算 13.5s（seed 1 take）/ 15.8s（seed 4 grow），改后 3.6s / 4.5s；36 局逐项对拍（胜者、结束天数、每人资产、存活、出局日）完全一致。

普通收入和得卡不再逐条阻塞台词；移动 140ms/格，AI 决策间隔 220ms（统一配置在 experience.js）。实际人类局长尚待测量，不把 16 天换算成未经验证的分钟数。

```powershell
node --test
node tools/play.mjs --slice --seed 7
node tools/evaluate-slice.mjs --seeds 20
```

调试会话每行一个 JSON 请求，例如 `{"op":"observe"}`、`{"op":"auto","count":10}`、`{"op":"answer","promptId":1,"value":{"action":"roll","dice":1}}`。返回独立的可序列化快照、待决策、局面、手牌与最近因果；旧 promptId 会被拒绝。它驱动真实引擎，不是另一份模拟规则。

针对性测试覆盖：翻修→旺季→停业→恢复；收购付款与归属一致、溢价有真实资产代价、书屋不能被远程抢；逐个枚举真实移动分支并与精确落点预览比较；实际渲染函数在 Node 中生成行动/补给/落点/结算界面；AI 不读未来随机数、可结束全局。

本轮验证：`node --test` 120 项通过，`git diff --check` 与浏览器入口模块语法检查通过。额外 Node DOM 适配器执行真实 `main.js` 的开局、选卡、地图选目标与两卡预算，验证地图租金 2,800→5,600→11,200 及日志别名一致；24 组医院/监狱侧路场景与实际结算位置一致。本地 HTTP 对入口、模块、样式均返回 200。这些不是浏览器视觉截图验证。

## 自测改变过的设计

首次 120 局中允许远程收购书屋，机会买家赢 99 局。这个方案被撤回：书屋改为必须到场购买，小店收购付原主人全款并增加25%溢价。随后发现 AI 机械收购会把现金送给卖家、最后几天升级会烧掉资产，因而增加剩余时间与机会成本的评估。自测用于淘汰明显坏机制，不证明人类乐趣或最终平衡。

独立复查还发现「没有银行却把租金存入无法投资的存款」和第三出生点过远，分别改成租金现金入账与相近接近距离。早期中央开局抢购偏向先手，改为公开的第4天开售。卡牌显示名称与日志原内部名称不一致，也统一为翻修/旺季/停业/定步/收购，并用店名替代内部坐标。

## 尚未验收

- 真人是否会主动规划、理解事件并想再开一局；这是用户反馈检查点。
- 除上述指定场景外的浏览器视觉布局，以及真机触屏、声音与真人局长：Node 渲染和 CDP 鼠标回执不能替代这些验证。
- 多策略长期平衡、先后手及地图起始位置偏差。保留可复跑实验，不以几次胜率调整宣称平衡完成。
- 卡图、人物魅力与聚会感还没有完成，仅沿用现有 SVG 语言。下一片是否增强这些，取决于本片核心选择是否值得保留。

**手机窄屏「读得到 + 点得到」（#3264，本地已验收，未发布）**：[预登记、原始回执与可复跑驱动](../.scratch/3264-mobile-commit/)。普通入口 `/?slice=1&style=grow&seed=1`，390×844 无头 Chrome（真 CDP 鼠标输入，不是模拟点击），中文用 scratch 里的 Noto CJK 字体渲染并逐字哈希验字形——**此前所有 390px 截图都是豆腐块，它们从没证明过可读性**。

本片买的是三件不同的事，分别有回执：①**加盖屏可达**：`[data-act="build"]` 与 `[data-act="skip"]` 从 `hit:false`（rect 986.7..1021.1，`#hand` 裁切线 837.3）变成 `fit.visible=full`、`hit=true`，真按下后 `playerCard` 从「现 42k 存 0」变「现 32k 存 0」且面板收起。②**补给屏可翻看、可任选**：四个选项 `533.5..619 / 631..698 / 710..795.6 / 799.6..834` 全部 `full`、全部 `hit=true`，按下**第 2 个**（修前 `hit:false`）后日志写「选择「找机会接盘」：收购 + 定步」、手牌 3→5、面板收起。③**提示不再说假话**（见下）。两屏的固定板规则都严格限 `#choice` 内的 `:has([data-act="build"])` / `:has(.supply-options)`，不动 #3166 的 8 条 `:has`、不动引擎。

**本片我自己造的 bug，写在这里因为它差点以「通过」交付**：把 `#choice` 提成 `position:fixed` 之后，它脱离了祖先裁切，但 `visibleBounds()` 仍沿 `parentElement` 把所有裁切祖先的矩形取交，于是补给屏四个选项全在屏上、全可点，屏幕却挂着「↑ 还有 2 个补给选项在上面」。量具 `MEASURE_CORE` 早就有 `fixed` 规则，`visibleBounds` 没有——两把尺子不一致。修法是让 `visibleBounds` 在 `position:fixed` 节点处停住（自己算裁切者，不再往上累加），并补一条会先红后绿的回归 `test/hint-live.test.js` D。**教训：把元素提到 fixed 会同时改变「玩家看到什么」和「代码怎么算看到什么」，后者必须一起改，且要有先在旧字节上变红的测试。**

## #3319 选街屏：屏幕在劝你选错的那一条（本地已复验）

首局里最像「两个都说得通」的时刻，是第 4 天手上有旺季、自己两条街还没进旺季的那一屏。
把卡点开之后发现：**面板的排序键和卡面说的不是同一件事**，两屏互相打脸。

- **排序键错了**：面板按「对手每次租金的变化」降序，卡面/补给屏按「对你的净收益」，

## #3320 对照入口的隔离，与「回执从哪来」（本地已复验，未推送）

这一轮不改玩法，改的是**证据**：一次「哪些文件能被发出去」的收口，一次「回执能不能被核对」的收口。

**对照入口（8001）还是前缀白名单。** `SERVABLE_PREFIXES = ('/src/',)` 的形状和黑名单一样：
之后落进 `src/` 的任何文件都**自动**可下载，不需要任何人再做决定。实测现状：
`/src/debug/session.js` 200、`/src/sim.js` 200、`/src/debug/` 与 `/src/data/maps/` 200 **且是目录列表**。
现在 `SERVABLE_MODULES` 逐文件列 29 个产品模块，并重写 `list_directory()` 直接回 404
（目录列表是另一种泄漏：白名单判的是 URL，目录不在名单里就会一路走到父类的列目录分支）。
名册不靠手抄 —— `test/serve-variant-allowlist.test.js` 顺着真实 import 图逐条比，
产品加模块忘登记就红并指名缺哪个；另有一条在 `src/` 下**新写一个文件**再去取它，
这是唯一能把「逐文件」和「前缀」分开的检查。

**判据自己也修了一处。** 把 `is_servable` 改回前缀放行 → 2 条红；但删掉 `list_directory`
只让**新增的直接单测**红，HTTP 那几条照样绿 —— 因为 `/src/debug/` 在 `is_servable` 就被拒了，
根本走不到列目录分支。**HTTP 层咬不住它**，所以补了一条直接考函数的测试。

**回执：能重判 ≠ 能核对。** `receipt-3319-390` 点名的 `OUT-3319-final` 不存在，
它记的三个 raw sha256 与盘上任何 `OUT-*` 都不合（`OUT-*/` 被 `.gitignore` 挡着，清理一删就没了）。
它的 PASS 是真的，它「从哪来」不是。改法：`make-receipt.py` 把 raw 字节 gzip **一起发进回执**
（317 KB → 约 16 KB），新增 `verify-receipt.py` 让人只拿回执就能核哈希、核剪裁（slim 必须
**正好是** raw 减去声明字段，防「偷偷多剪」）、并复判。这一轮新收三份可自证回执：
`receipt-3319i-tree`（其 35 个文件与交付锁逐个相合 ⇒ 交付那棵树真的打完了一整局）、
`receipt-3320-390`（本轮新跑）、`receipt-3317-390`（源还在，重切后与已发 slim 逐字节相同；
它是一次**真 FAIL**，那正是 #3319 故意判红的那次）。`receipt-3319-390` 保留并加
`UNVERIFIABLE.md`，由测试要求「没有 raw/ 就必须有这份说明」。

**边界**：`serve.py`（8000）有同样的目录列表泄漏（`/support/`、`/docs/` 200 且是列表），
但它在 35 项字节锁里，动它要重签整份交付 —— 这一轮没动，是有意的取舍。
