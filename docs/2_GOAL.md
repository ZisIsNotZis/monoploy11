# 目标

## 当前目标（2026-11-13 对齐）

最终目标是「爱玩」：玩家愿意主动打开、结束后惦记下一局，也愿意推荐给朋友。项目追求 minimal 与乐趣的平衡，是轻量单网页、相对精简但完整的独立游戏；不照搬用户另一个更复杂的项目，不以内容数量、规则复刻或测试通过代替乐趣。

用户实测的关键证据是：学习累、事情没看懂就过去了、试玩主要出于项目责任而非想玩。复杂度并非唯一原因；需要同时建立值得期待的行动与理解后的回报。游戏王是用户提供的偏好线索（玩法、卡图、设计、故事），不是照搬其规模与规则负担的指令。

当前可逆假设：先做「一个人也愿意主动玩的、带聚会气质的轻策略对局」，以计划、组合、对抗、可解释的结果形成重玩动力。party、roguelite、战役、长期解锁、工坊尚未决定为产品承诺。

工作方式是 vertical slice：小型完整体验 → 自测与公开信息 AI 实验 → 有价值时邀请用户试玩 → 根据反馈改下一片。用户已授权自主推进和必要的 subagent 自测。通过规则测试只意味着逻辑证据；「爱玩」仍需人类体验。

当前切片设计、验证证据与下一步见 [6_SLICE.md](6_SLICE.md)，工作状态见 [0_ROADMAP.md](0_ROADMAP.md)。

## 既有完整模式基线（历史设计参考，非本轮验收清单）

Monopoly 11 是一款纯前端的回合制棋盘游戏：玩家轮流掷骰、沿道路移动、买地、建房、收租、使用卡片、经营现金和存款，最后按队伍总资产或破产结果决出胜负。它打开就是可玩的一局，不需要后端、登录、构建步骤或联网请求。

一局至少有 2 名参赛者，没有人数上限。每名参赛者独立选择人类或 AI、队伍、颜色；全人类、全 AI、人机混合都合法。一局中至多一名参赛者可以是 角色；角色 是初始配置和技能不同的独立参赛者，有三个档位，和所有人一起排队、掷骰、买地、收租、破产。所有地图共享同一套核心规则；每张地图可以在数据中声明自己的路线、地形、初始建筑和地图机关，地图规则必须显式写在规则书和地图数据里，不做隐藏规则。默认地图集有 12 张地图，每张地图至少有一个改变路线、时间、估值或初始局面的签名机制，不能只换主题和刷新表。

游戏包含角色与天赋、角色及三档技能、52 张卡与五合一进阶、10 位神仙、7 种大建筑、地产与租金、现金与存款、银行、股票、乐透、商店、魔法屋、新闻、野狗、乞丐、神秘人、医院和监狱。结盟不是本游戏的系统。

棋盘固定为网格：路面 1×1 可走，小地产 1×1，大地产是一整块矩形（默认 2×2，地图可定义 1×2、2×1、2×3、3×2、3×3）放在路边且不可走，路面上的东西是独立的第三层，每格最多一个；小地产必须贴路，大地产不是两格路，也不拆成多个小地产；同一条街的地产连成不超过五块的簇，簇间留空，每簇最多一块大地产。所有人随机位置、随机朝向，起始格不触发结算；地图可以预置无主联排房屋、无主大建筑和中立地标，无主已建地产在买下前不产生租金。

优先级依次是：规则闭环与结算顺序正确；一局能从随机开局走到胜负；内容覆盖完整；操作与显示紧凑清晰；成本保持零付费素材、零后端、零构建依赖。美术、语音和音乐属于后期体验层：2D 标识、头像、角色台词、浏览器 TTS、BGM 和轻量 CSS 动画可以后补，缺素材时退化为文字。

界面固定为右侧落地侧栏：上方状态、中间日志、底部情境区；没有顶栏、底栏、重开按钮和银行按钮，股票按钮常驻。所有选择在右侧栏完成，空间目标回到地图点击。金额、卡片和状态变化以飘字显示在角色头顶。

完整规则以 `docs/3_REQUIREMENT.md` 为准。
