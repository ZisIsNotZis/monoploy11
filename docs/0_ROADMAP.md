# 路线

目标是用纯前端做一个网格棋盘的《大富翁 11》规则复刻：三层棋盘、热座、可结盟、规则型 AI，无后端。预算上限 ¥100，预期不产生现金支出。

路线按竖切片推进，每个里程碑都必须是用户能打开、能玩、能判断的东西。资料整理和规则研究不算里程碑，它们是 M1 的前置工作。

## 当前状态

M1 已经是一张 25×17 网格图上的完整热座切片：N 名玩家随机落位、随机朝向，无 AI 也能开局；引擎覆盖三层棋盘、移动与方向、地产买卖与加盖、租金、现金存款、银行利息、股票、乐透、商店、研究所、魔法屋、新闻、神秘人、野狗、乞丐、医院、监狱、传送、随机刷新的地面道具、48 张卡与五合一、10 位神仙、7 种大建筑和 4 位领主 × 3 档。界面是右侧可拖宽的落地侧栏，玩家状态压成一行式，日志占中间，底部情境区负责所有选择；地图不写文字，用方形图块和图标占位，大地产画成一整块 2×2，人物是带方向指针的圆。方向选择、炸弹与障碍等选格操作直接点地图；商店只显示卡面占位和价格，按侧栏宽度自动排列；金额变化飘在角色头顶。固定种子可以复现，无头模拟可以跑完整对局。

当前还缺的不是框架，而是收尾和内容：魔法屋只有占位选项，缺已证实的“获得三张卡片”，其余选项没有资料依据；冻结或冰冻状态的 0 点规则只有规则位，没有状态来源；结盟、背叛和 AI、16 张图、热斗/抢房、体验层素材还没有做。还有一部分角色天赋只有数据没有钩子。数值都是近似值，乐透十天和银行三十天是暂定值。

## 里程碑

M1 是现在这张单图、热座、无 AI 的竖切片。它的完成标准不是“代码里有个函数”，而是用户能在浏览器里开一局，把买地、收租、用卡、银行、股票、乐透、商店、大建筑、领主这些系统都至少触发一次，并且同一 seed 重跑结果一致。M1 的地图只保证规则闭环和三层关系，不保证还原某张原版地图。

M2 把内容补齐：16 名角色天赋、48 张卡的全部获取与结算、10 位神仙、7 种大建筑、4 位领主 × 3 档、16 张按网格重画的地图、热斗和抢房、规则型 AI、结盟的提议/接受/背叛，以及魔法屋、新闻和事件的全部选项。验收以“每个天赋在对应触发下生效、每张卡有获取路径、每档领主只启用该档技能、所有地图校验器全绿、AI 能独立打完一局、结盟改变租金与胜负”为准，同时把 M1 遗留的路面与地产同点结算补完整。

M3 是体验层：2D 标识与头像、角色台词、浏览器 TTS、BGM 与音效、金币飞字、骰子/移动/爆炸的轻动效、地图配色、资产榜和新闻横幅、选人开局界面、快捷键与跳过动画。动画只用 CSS 和短过渡，不做逐帧。验收标准是关掉素材仍能完整游玩，打开素材有辨识度和反馈，页面不产生外部网络请求，移动端能操作。

M4 做平衡与发布：调平近似数值、重写 README、静态部署、跑 1000 局模拟、写发布报告。验收标准是公开链接可玩，README 能在三十秒内讲清怎么开始以及哪些完成、哪些没完成，1000 局模拟无死锁。

## 路线选择

棋盘选择网格而不是先画拓扑，是因为原版的信息主体是路面、路边地产和路面上的东西三层关系，不是一张抽象图；网格能让这三层各自独立，能让大地产成为一整块 2×2，也能让选格卡片直接落在地图上。代价是原版地图需要重画，旧环图只保留为测试数据。死路选择反弹而不是强制传送，是因为死路本身是地图设计问题，不该用逻辑补丁把玩家瞬移走；传送门只是一个可选路面类型。

商店和神秘人选择落点触发而不是经过触发，银行、乐透、送卡格和地面道具才在经过时生效。购买选择只用现金、租金进入存款，是为了让银行和取款有实际意义。大地产选择先买空地再选建筑，公园只能被改建卡改成，是为了保留原版的二次投资节奏。界面选择右侧栏底部情境区而不是中间弹窗，是为了不遮地图；方向与选格操作回到地图点击，是因为按钮无法表达“周围全是路”时的空间关系。

不做的东西是明确的：小游戏、3D、剧情、成就、装扮、实时联机、账号、匹配、手柄、逐帧动画、股票 K 线、隐藏系数逐帧反推、资料不足地图的逐格还原。资料边界是 16 名角色、16 张图、4 位领主、48 张卡；国服改名版不单独复刻，只在数据表里留别名。热斗和抢房属于 M2，实时联机永久不做。
